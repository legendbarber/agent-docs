# 컨텍스트·문서 유지관리 프로토콜

> 요약: 세션에 불필요한 정보가 들어오지 않게 하고, 남겨야 할 사실·검증 근거를 보존하면서 작업 문서를 압축·정리하는 절차.
> 읽을 때: 문서 정리 점검 시점이 되었거나, 상태·계획·색인이 비대해지거나 중복·오래된 정보가 발견되었을 때만.

## 목표와 원칙

- **목표:** 기본 로드 지침·상태 문서의 크기와 재개에 필요한 조회량을 줄인다. 파일이 많다는 사실 자체는 컨텍스트 사용량을 늘리지 않는다. **실제로 읽는 내용**을 줄이는 데 집중한다.
- **안전:** 원본 데이터·고객 자료·실제 코드·운영 설정·계약·법정/감사 기록·증빙 파일은 자동 축약·삭제하지 않는다. 중요 결정·미해결 위험·사용자 제약·검증 근거 위치도 유지한다.
- **선택성:** 전체 작업 공간 일괄 스캔 금지. 현재 작업에서 이미 읽거나 변경한 문서와 참조 인덱스만 먼저 확인한다. 근거가 분산되어 있거나 사용자 요청이 전체 점검인 경우에만 범위를 확대한다.
- **출처:** 원본은 요약보다 우선한다. 요약한 사실에 원본 경로·섹션·관측 시점 등을 연결하고, 미검증 추측을 확인된 사실로 격상하지 않는다.

## 언제 수행하나?

1. **가벼운 정리:** 복합 업무의 **각 주요 단계 종료 또는 중단 시**, 이미 수정한 `current-status.md`와 해당 작업 계획의 중복·오래된 단계 정보만 정리한다. 별도 문서 전체 읽기 없이 수행 가능하다.
2. **집중 정리:** 주요 단계 **3개 완료마다**, 업무가 최종 검증을 통과한 시점, 또는 상태·색인이 너무 길어 다음 행동을 찾기 어렵거나 서로 충돌할 때 실행한다. 카운트는 작업별 계획의 재개 카드에 남긴다.
3. 시계 기준 자동 주기가 아니다. 작업이 실행되지 않는 동안 혼자 돌아가지 않는다. 시간 예약 실행은 별도 스케줄러·워크플로가 필요하다.
4. 정리가 하나의 주요 단계를 넘길 정도로 커지면 별도 유지관리 단계로 나누고, 사용자 업무의 검증을 밀어내지 않는다.

## 무엇을 남기고 무엇을 줄이나?

| 정보 | 처리 |
| --- | --- |
| 현재 목표·사용자 제약·단계·다음 행동 | 짧은 재개 카드에 **유지** |
| 완료 조건, 실패·미검증, 승인 필요 사항 | 해결·검증 전까지 **유지** |
| 중요한 기술·운영 결정과 이유 | `decisions.md`에 한 번만 **유지** |
| 테스트 결과·로그·출처 | 필요한 결론과 **검증 가능한 원본 위치**만 인계 문서에 기록; 원본은 보존 |
| 상세 도구 호출 내역·실패한 검색 시도 | 재개에 의미 없으면 인계 문서에 **복사하지 않음** |
| 완료한 단계의 반복 서술 | 검증 상태·산출물 경로만 남기고 **중복 축약** |
| 오래된 활성 상태·고장 난 링크 | 실제 상태를 확인하고 수정; 확인 불가면 **미검증** 표기 |
| 완료·보류된 작업 계획 | 활성 인덱스에서 분리, 계획은 보존; 재개할 방법을 유지 |
| 민감 정보·인증값 | 문서에 기록하지 않음. 이미 노출된 값은 안전 절차에 따라 처리 |

## 실행 절차

1. **대상 제한:** 현재 인계 문서, 해당 계획, 이번 단계에서 변경된 내부 문서, 관련 인덱스 항목만 본다. 그 밖의 문서는 필요한 경우에만 연다.
2. **사실 확인:** 실제 파일·시스템·검증 결과와 대조해 살아 있는 목표·결정·미해결 항목을 식별한다.
3. **짧게 교체:** 중복 문장은 삭제하고, 과거 단계의 긴 서술은 '검증된 결론 + 근거 위치'로 교체한다. 같은 사실을 여러 문서에 복제하지 않는다.
4. **연결 점검:** 상태 문서의 작업 ID·계획 경로·다음 행동과 문서 상단 요약·인덱스의 경로가 맞는지 확인한다.
5. **보존 확인:** 중요한 근거의 원본 경로가 실제로 열리는지 확인한다. 확인하지 못하면 미검증으로 남긴다. 원본의 안전한 보존이 불확실하면 요약·삭제 대신 보류한다.
6. **종료:** 작업 재개에 필요한 정보가 남았는지 점검한다. 정리 결과(압축한 문서·고친 참조·남은 문제)를 간단히 보고한다. 실제 토큰 절감은 측정하기 전까지 주장하지 않는다.

## 하지 말 것

- 한 줄의 요약을 원본·사용자 요구사항·최종 검증의 대체물로 사용하지 않는다.
- 전체 Markdown 파일을 정기적으로 재작성하거나 인덱스에 자동 등록하지 않는다.
- 사용자 산출물, 증빙, 원본 자료, 다른 작업의 계획을 유지관리 명목으로 덮어쓰거나 삭제하지 않는다.
- 안전한 복구 수단과 필요한 승인 없이 파일을 물리적으로 삭제·이동하지 않는다. 아카이브 이동도 링크와 재개 경로를 먼저 확인한다.
- 보안·운영 사고를 단순하게 보이기 위해 실패·미검증 기록을 제거하지 않는다.
