# Agent Docs — 범용 세션 연속성·단계 실행 템플릿

Codex 등 `AGENTS.md`를 읽는 에이전트가 **작업 종류와 무관하게** 동일한 운영 규칙을 적용하고, 세션이 바뀌어도 저장된 상태로 작업을 이어갈 수 있게 하는 경량 템플릿이다.

핵심 목표는 두 가지다.

1. **세션 간 연속성:** 새 세션마다 짧은 상태 인덱스를 확인하고, 관련 작업의 계획·검증 결과·다음 행동을 복원한다.
2. **단계별 실행:** 복합 요청에서는 에이전트가 스스로 단계를 분할하고 단계별 완료 조건과 검증 방법을 만든다. 한 응답에서 주요 단계 하나만 실행하고 인계한다.

코드 작성에만 한정하지 않는다. 조사·분석, 문서 분석·작성, 데이터 정리, 시스템·서버 관리, 자동화, 운영 절차 등 도구와 권한이 허용하는 작업 전반을 대상으로 한다.

## 파일 구성

```text
AGENTS.md                         # 모든 작업에 적용하는 핵심 동작 규칙
CLAUDE.md                         # Claude Code에서 AGENTS.md를 참조
agent-docs/current-status.md      # 새 세션이 먼저 읽는 작업 인덱스
agent-docs/plans/TEMPLATE.md      # 복합 작업의 단계·완료 조건·검증·인계 형식
agent-docs/plans/<task-id>.md     # 필요할 때 에이전트가 생성하는 실제 작업 계획
agent-docs/decisions.md           # 장기간 영향을 주는 중요 결정만 기록
agent-docs/repository-map.md      # 코드 저장소에서만 필요 시 활용하는 선택 문서
```

`plans/<task-id>.md`는 예시 경로이며, 작업이 시작될 때 생성한다. 간단한 작업에는 계획 파일이 필요 없다. `repository-map.md`는 코드 작업을 위한 선택 자료이므로 일반 업무의 필수 단계가 아니다.

## 기본 동작

1. **새 세션 시작:** `AGENTS.md` 규칙을 적용하고 `current-status.md`에서 진행 중인 작업을 찾는다. 새 요청이 다른 작업이라면 기존 상태를 보존한다.
2. **요청 분류:** 단순 작업은 바로 수행한다. 여러 단계가 필요한 작업이라면 목표·제약·산출물을 확인해 계획 파일을 만든다.
3. **에이전트가 완료 조건 생성:** 각 단계의 산출물에 따라 검증 가능한 조건과 확인 방법을 스스로 정한다. 사용자 기준이 있다면 그것이 우선한다.
4. **한 단계 실행:** 현재 단계에 필요한 하위 작업을 수행하고 결과를 검증한다. 다음 주요 단계로 자동 진입하지 않는다.
5. **인계:** 계획과 상태 인덱스에 결과, 확인된 근거, 미충족 조건, 다음 한 가지 행동을 기록한다. 다음 세션에서도 이어서 수행할 수 있다.

## 작업별 완료 조건 예시

다음은 고정 규칙이 아니라, 에이전트가 각 작업을 계획할 때 참고할 수 있는 예시다.

| 작업 유형 | 에이전트가 생성할 수 있는 완료 조건과 검증 |
| --- | --- |
| 문서 분석 | 요청한 질문에 답하고, 핵심 주장에 원문 위치·출처를 연결하며 불확실성을 명시함 |
| 문서 작성 | 요구한 독자·형식·구조를 반영하고 사실·표현·누락 항목을 점검함 |
| 조사·리서치 | 최신성·신뢰성에 맞는 자료를 확인하고 비교 기준과 판단 근거를 공개함 |
| 데이터 처리 | 원본 보존, 변환 결과 정합성, 누락·중복 등 품질 검사를 확인함 |
| 코드·설정 | 요청 기능과 제약을 충족하고 관련 테스트 또는 동등한 검증을 수행함 |
| 서버·시스템 운영 | 변경 전 상태와 위험을 확인하고, 허가된 작업 후 서비스 상태·로그·지표를 점검함 |
| 기타 업무 | 요청한 산출물의 특성에 따라 관찰 가능한 완료 조건을 새로 정함 |

작업을 실제로 실행할 수 있는지 여부는 접근 권한, 연결된 도구, 승인 절차에 따라 달라진다. 템플릿 자체가 서버 접근 권한이나 외부 서비스 실행 능력을 제공하지는 않는다.

## 세션 연속성을 위한 주의 사항

- `AGENTS.md`는 지침을 적용하는 수단이지 세션 간 대화를 자동으로 공유하는 기억 장치가 아니다. 같은 작업 상태 파일에 접근할 수 있어야 한다.
- `current-status.md`는 짧게 유지하고 상세 단계는 작업별 계획에 기록한다. 모두를 매번 읽지 않는다.
- 상태 파일은 현재 사실과 달라질 수 있으므로 실제 자료·파일·서비스 상태와 대조한다.
- 여러 작업이 있으면 계획을 작업 ID로 구분하고, 서로 관련 없는 요청 때문에 이전 작업을 덮어쓰지 않는다.
- 중요한 작업 상태는 공유되거나 지속되는 저장소에 기록해야 한다. 로컬 파일을 다른 환경에서 사용할 수 없으면 인계도 되지 않는다.

## 도입 방법

1. 사용할 작업 공간(저장소나 지속되는 디렉터리)에 템플릿 파일을 복사한다.
2. 작업 공간의 목표·제약이 있다면 `AGENTS.md`에 짧게 추가한다. 공통 규칙을 불필요하게 중복하지 않는다.
3. 코딩 프로젝트에서만 `repository-map.md`의 비자명한 구조 정보를 채운다. 일반 업무라면 비워 두거나 제거해도 된다.
4. 새 작업을 요청한다. 복합 업무에서 계획 문서와 완료 조건을 자동 생성하는지 확인한다.
5. 다른 세션을 열어 해당 작업의 다음 단계를 요청하고, 저장된 상태를 근거로 재개되는지 확인한다.

모든 프로젝트에 공통 규칙을 쓰려면 Codex의 전역 `~/.codex/AGENTS.md`에 공통 지침을 배치할 수 있다. 다만 작업별 상태 파일과 산출물은 해당 작업 공간에 따로 유지해야 한다.

## 유지 관리

- `AGENTS.md`: 모든 작업에 적용되는 동작 규칙에 변경이 생길 때만 갱신한다.
- `current-status.md`: 복합 작업의 단계 완료·중단·재개 시 갱신한다.
- `plans/`: 복합 작업에서만 사용한다. 이력 나열이 아닌 최신 계획과 인계 상태 중심으로 유지한다.
- `decisions.md`: 후속 작업의 선택에 영향을 주는 결정만 기록한다.
- `repository-map.md`: 코드 작업에서 쉽게 확인할 수 없는 책임 경계가 있을 때만 사용한다.

변경 로그, 도구 사용 내역, 원문을 그대로 복제한 기록을 쌓지 않는다. 오래된 정보와 중복을 정리해 컨텍스트 비용을 제한한다.
